# Research: Электрондық қолтаңба утилитасы

## 1. Жобаның тақырыбы

**Жоба атауы:** Электрондық қолтаңба утилитасы  
**Пәні:** Жүйе қауіпсіздігі  
**Негізгі технологиялар:** Java, RSA-2048, SHA256withRSA, PEM.

## 2. Зерттеудің мақсаты

Бұл зерттеудің мақсаты — электрондық құжаттың авторын растауға және құжаттың өзгермегенін тексеруге арналған электрондық цифрлық қолтаңба утилитасының теориялық негіздерін қарастыру.

Жүйе құжатқа қол қою үшін ашық және жабық кілттен тұратын RSA кілт жұбын пайдаланады. Қол қою кезінде SHA-256 хэш-функциясы мен RSA алгоритмі біріктірілген `SHA256withRSA` қолданылады.

## 3. Электрондық цифрлық қолтаңба туралы түсінік

Электрондық цифрлық қолтаңба (ЭЦҚ) — электрондық құжаттың түпнұсқалығын және тұтастығын тексеруге мүмкіндік беретін криптографиялық дерек.

ЭЦҚ үш негізгі міндетті орындайды:
- **Түпнұсқалықты растау:** қолтаңбаның тиісті жабық кілт арқылы жасалғанын тексеруге көмектеседі.
- **Тұтастықты сақтау:** құжат қол қойылғаннан кейін өзгертілсе, тексеру нәтижесі сәтсіз болады.
- **Авторлықты растауға көмектесу:** жабық кілт иесінің қолтаңбасын тексеруге мүмкіндік береді. Алайда кілттің нақты кімге тиесілі екенін анықтау үшін сертификат және сенімді сәйкестендіру қажет.

## 4. RSA-2048 алгоритмі

RSA — ашық кілтті криптография алгоритмі. Ол бір-бірімен математикалық байланысқан екі кілтті пайдаланады:

- **Жабық кілт (Private Key):** құжатқа цифрлық қолтаңба қою үшін қолданылады және құпия сақталуы керек.
- **Ашық кілт (Public Key):** жасалған қолтаңбаны тексеру үшін басқа пайдаланушыларға берілуі мүмкін.

RSA-2048 атауы кілт ұзындығының 2048 бит екенін білдіреді. Java тілінде кілт жұбын `KeyPairGenerator` класы арқылы жасауға болады.

## 5. SHA-256 және SHA256withRSA

SHA-256 — кез келген көлемдегі деректен тұрақты ұзындықтағы 256 биттік хэш мәнін есептейтін хэш-функция. Құжаттың мазмұны өзгерсе, оның хэш мәні де өзгереді.

`SHA256withRSA` — құжаттың хэшін RSA алгоритмімен қолтаңбалау және оны тексеру үшін қолданылатын Java криптографиялық алгоритм атауы. Java тілінде бұл операциялар `Signature` класы арқылы орындалады.

Қол қоюдың жалпы кезеңдері:
1. Құжаттың байттары оқылады.
2. `Signature` объектісі `SHA256withRSA` алгоритмімен алынады.
3. Объекті жабық кілтпен инициализацияланады.
4. Құжат деректері `update()` әдісімен беріледі.
5. `sign()` әдісі цифрлық қолтаңбаны жасайды.

Тексеру кезінде ашық кілт пайдаланылады: `initVerify()`, `update()` және `verify()` әдістері орындалады.

## 6. PEM форматы

PEM — криптографиялық кілттер мен сертификаттарды мәтіндік түрде сақтауға арналған кең таралған формат. PEM файлында Base64 кодталған дерек және арнайы тақырып/аяқтау жолдары болады.

Жиі кездесетін белгілер:
- `-----BEGIN PRIVATE KEY-----`
- `-----BEGIN PUBLIC KEY-----`

Жабық кілт файлына қолжетімділік шектелуі тиіс. Оны ашық репозиторийге, ортақ чатқа немесе жалпыға қолжетімді орынға жүктеуге болмайды. Нақты PEM түрі қолданылатын кодтау тәсіліне және кілт контейнеріне байланысты.

## 7. Java бағдарламалауындағы негізгі кластар

| Класс | Қызметі |
|---|---|
| `KeyPairGenerator` | RSA кілт жұбын генерациялайды |
| `KeyPair` | Ашық және жабық кілттерді бірге сақтайды |
| `PrivateKey` | Қол қоюға арналған жабық кілт интерфейсі |
| `PublicKey` | Қолтаңбаны тексеруге арналған ашық кілт интерфейсі |
| `Signature` | Құжатқа қол қою және қолтаңбаны тексеру операцияларын орындайды |
| `Files` | Құжат пен кілт файлдарын оқуға/жазуға көмектеседі |

## 8. Жүйенің жұмыс істеу логикасы

Жүйенің негізгі жұмысы екі процесс арқылы орындалады:

**Қол қою процесі:** пайдаланушы құжатты таңдайды → жүйе жабық кілтті қолданады → `SHA256withRSA` қолтаңбасы жасалады → қолтаңба жеке файлға сақталады.

**Тексеру процесі:** пайдаланушы бастапқы құжатты, қолтаңбаны және ашық кілтті береді → жүйе қолтаңбаны тексереді → нәтиже «қолтаңба дұрыс» немесе «қолтаңба жарамсыз» түрінде көрсетіледі.

## 9. Қауіпсіздік талаптары

- Жабық кілт құпия сақталуы және оған рұқсатсыз қолжетімділік шектелуі керек.
- Жабық кілтті GitHub репозиторийіне немесе басқа ашық ортаға жүктемеу қажет.
- Қолтаңба тексерілгенде дәл сол құжат байттары қолданылуы тиіс.
- Қолтаңба файлы мен ашық кілттің қай құжатқа тиесілі екені анық көрсетілуі керек.
- Кілт жоғалған немесе жария болып кеткен жағдайда оны жарамсыз деп есептеп, жаңа кілт жұбын жасау қажет.
- RSA-2048 кілті мен сенімді криптографиялық провайдерді пайдалану керек.
- Қолтаңбаның дұрыс шығуы өздігінен адамның жеке басын дәлелдемейді; ол үшін сертификаттау және кілт иесін тексеру тетіктері қажет.

## 10. Қорытынды

Зерттеу нәтижесінде электрондық қолтаңба утилитасының негізгі теориялық компоненттері қарастырылды. RSA-2048 ашық/жабық кілт жұбын құруға, SHA256withRSA құжатқа қол қою мен қолтаңбаны тексеруге, ал PEM кілттерді мәтіндік форматта сақтауға мүмкіндік береді. Java тіліндегі `KeyPairGenerator` және `Signature` кластары осы жүйенің негізгі криптографиялық бөлігін құрайды.
